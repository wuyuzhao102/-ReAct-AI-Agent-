# 🛠️ 开发环境与接口约定

> 本文是**四人必须共同遵守的技术约定**。写代码前先读一遍，避免到最后才发现端口冲突、字段名不一致、依赖版本打架。
> 当前处于前置准备阶段，**以下内容为约定，尚未落地代码**。

> 📌 每个人的版本务必对齐。**装好后在群里报一下 `java -version` / `node -v` / `python --version` 的输出。**

| 服务 | 端口 | 访问地址 |

| Spring Boot 业务服务 | **8080** | http://localhost:8080 |

## 3. 接口约定

### 3.1 路径前缀

| 服务 | 前缀 | 示例 |
| :--- | :--- | :--- |
| 前端调用 Java 业务服务 | `/api/**` | `POST /api/auth/login` |
| Java 调用 Python Agent | `/agent/**` | `POST /agent/chat` |
| 健康检查 | `/actuator/health`、`/health` | —— |

前端 Vite 开发环境通过 proxy 把 `/api` 转发到 `http://localhost:8080`，**前端代码里不要写死 `localhost:8080`**。

### 3.2 统一返回格式（Java 侧）

```json
{
  "code": 0,
  "message": "ok",
  "data": {}
}
```

- `code`：`0` 成功，非 0 为业务错误码（`1001` 未登录、`1002` 无权限、`2001` 文件类型不支持……）
- 分页数据统一放在 `data` 中：`{ "list": [], "total": 0, "page": 1, "size": 10 }`

### 3.3 认证方式

- 登录成功后返回 **JWT**，前端存在 `localStorage`，后续请求带 `Authorization: Bearer <token>`。
- 除 `/api/auth/**` 外，其它接口都需要鉴权。

### 3.4 Java ⇄ Python 的契约

`POST /agent/chat`

```json
{
  "userId": 1,
  "sessionId": "uuid",
  "coursewareId": 12,
  "question": "下周要考高数极限，帮我复习"
}
```

返回：

```json
{
  "answer": "（Markdown 文本）",
  "trace": [
    { "step": 1, "thought": "...", "action": "search_courseware", "observation": "..." }
  ],
  "finished": true
}
```

> `trace` 字段是**我们项目的答辩亮点**：前端可以把 Thought/Action/Observation 展开给学生看，体现"可解释的智能体"。

## 4. 数据库约定

- 库名：`coursemate`，字符集 `utf8mb4`，排序规则 `utf8mb4_unicode_ci`。
- 表名：小写下划线，统一前缀 `t_`，例如 `t_user`、`t_courseware`、`t_chat_message`、`t_note`、`t_wrong_question`。
- 主键：`id`，`BIGINT UNSIGNED AUTO_INCREMENT`。
- 必备字段：`created_at`、`updated_at`、`deleted`（逻辑删除，`TINYINT` 默认 0）。
- 所有表必须有注释（`COMMENT`），所有字段必须有注释。
- 建表脚本放在 `backend/sql/` 或根目录 `sql/`，**只提交建表脚本，不提交数据库数据文件**。

## 6. 密钥与配置管理 ⚠️

**永远不要把下面这些东西提交到仓库：**

| 内容 | 正确存放位置 |
| :--- | :--- |
| 大模型 API Key | `agent/.env`（已在 .gitignore 中屏蔽） |
| 数据库密码 | `backend/src/main/resources/application-local.yml` |
| JWT 密钥 | 同上 / 环境变量 |

**统一做法**：仓库里只提交**示例文件**，例如：

```properties
# .env.example（提交这个）
LLM_API_KEY=sk-your-key-here
LLM_BASE_URL=https://api.deepseek.com
DB_PASSWORD=your-password
```

组员复制一份改成 `.env`，填自己的值。

> 🚨 如果 Key 已经推到 GitHub：第一件事是去服务商后台**作废并重新生成**，第二件事才是在本地清理历史。只删文件是没用的，历史记录里还在。

## 8. 文件大小与 Git LFS

- 单个文件 **> 50MB**，GitHub 会直接拒绝推送；**> 100MB** 需要 Git LFS。
- 本项目的 PDF 课件、演示视频、答辩 PPT 原件**一律不进仓库**：
  - PPT / 文档定稿放组内网盘，仓库里只放 `.md` 版本；
  - 演示视频放网盘，README 里放链接。
- 确实需要版本管理大文件时再启用 Git LFS，**不要盲目执行**。

## 9. 质量底线（四人共同）

1. 提交前**自己能跑通**，不要把明显报错的代码推到 `dev`。
2. 不允许硬编码本地绝对路径（`D:\我的文件\...`）、个人账号、测试数据。
3. 不允许 `console.log`、`System.out.println("111")`、`print("test")` 这类调试输出留在交付代码里。
4. 不允许注释掉大段代码后提交（要留就写清楚 `// TODO: 原因 + 负责人`）。
5. 新增依赖要在 PR 描述里说明**为什么加**。
